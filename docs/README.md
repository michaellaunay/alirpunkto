# Documentation AlirPunkto

La documentation est bilingue ; **la version française fait référence**,
la version anglaise suit.

## Où trouver quoi

| Besoin | Aller à |
|---|---|
| Comprendre l'architecture actuelle | `fr/architecture/00_vue_d_ensemble.md` |
| Flux métier courants | `fr/specifications_fonctionnelles/` |
| Décisions et leurs raisons | `fr/architecture/decisions_architecture.md` |
| Journal des décisions au fil de l'eau | `fr/Journal de conception.md` |
| Audits de sécurité et revues de code | `fr/audits/` |
| Déployer (Docker ou hôte nu) | `../docker/README.md` |
| Intention initiale du projet (non normatif) | `fr/specifications_historiques/` |

## Principe de vérité

1. le code et les tests font foi ;
2. `architecture/` décrit le fonctionnement courant ;
3. `specifications_fonctionnelles/` décrit les flux métier retenus ;
4. `specifications_historiques/` garde l'intention initiale, **sans valeur
   normative** ;
5. les journaux de conception expliquent les changements de cap.

Le plan directeur de cette organisation est
`fr/Plan de refonte documentaire.md`
(traduction : `en/Documentation Refactoring Plan.md`).
